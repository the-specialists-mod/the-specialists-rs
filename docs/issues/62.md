# #62: Steam HL25 client: world stays black and the loading dialog never closes

## Description

Found while validating #23 on the Steam Half-Life 25th-anniversary client (Linux, build 10211, app build 15961492).

**What happens:** with the port's `client.so` and `ts.so` installed as `Half-Life/ts` (listen server on `ts_dojo`):
- The client connects (`CL_SignonReply 2`) and gameplay works: a scripted run joins, buys, spawns, uses a power-up, throws a grenade, dies, respawns, and four bots fight.
- But the 3D world is never drawn (black), and the VGUI2 "Loading… Parsing game info" dialog stays on screen for the whole session. Developer notify text does draw at the top.
- Stock Half-Life (`-game valve +map crossfire`) launched the same way renders normally, so this is the port's client, not the setup.

**Console:** nothing unusual apart from stock messages (`DemoPlayer::Init: couldn't get engine interface`, `System::AddModule`) and `PF_MessageEnd_I: Unknown User Msg 114` ×3 during spawn (`developer 1` only; messages sent before any client has received the user message table).

**How to reproduce:** assemble `~/.local/share/Steam/steamapps/common/Half-Life/ts` as `cargo xtask install` does (link `../ts` content, copy `game/ts`, copy the i686 `libts.so` to `dlls/ts_i386.so` and `dlls/ts.so`, and `libclient.so` to `cl_dlls/client.so`). Then, with Steam running:

```
SteamAppId=70 ~/.local/share/Steam/ubuntu12_32/steam-runtime/run.sh ./hl.sh -game ts -windowed -condebug +exec <cfg with map ts_dojo, waits, screenshot, quit>
```

Screenshots are written to `ts/HalfLifeNN.tga`.

**Suspects:** something in the client's per-frame exports that HL25 treats differently from FWGS, e.g. `HUD_GetStudioModelInterface` (the TS studio renderer, #2), `V_CalcRefdef` refdef fields (`nextView`, `onlyClientDraw`, viewport), `HUD_Redraw`'s return value, or the VGUI2/GameUI loading-plaque handshake.
