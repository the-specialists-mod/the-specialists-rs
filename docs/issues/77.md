## Description

Emitter and particle differences from TS's \`client.dll\`, found while working on #76. The emitter code is in \`crates/client/src/effects/emitters.rs\` (\`emit\`); TS's is at 0x1003ab40.

1. **The camera test is 2D in TS.** TS uses only the horizontal direction and distance (0x1003ace9–0x1003ae25): z is 0 in the dot product, and the distance is \`sqrt(dx²+dy²)\` with a floor of 1e-4. The box size isn't floored, so a size of 0 gives f = 10. The port uses 3D \`v::len(d).max(1.0)\` and \`.max(1.0)\` on the size.
2. **The inside test and count range.** TS uses a strict \`lo < cam < hi\` on x and y, without normalising min/max (0x1003ac75–0x1003acce). It passes \`random_long(ppelow, ppehigh)\` the raw values (0x1003ac54). The port's ranges are inclusive and normalised.
3. **Missing sprites are cached.** TS's 0x100509d0 retries \`SPR_Load\` and prints "WARNING! cannot found" on every miss. \`PSys::sprite\` (\`crates/client/src/effects/psys.rs\`) caches the failure and warns once.
4. **The ready flag isn't reset on VidInit.** TS clears 0x1018d16a ("TS_DrawEffects has run") on every \`HUD_VidInit\` (0x1006600f). \`effects::vid_init\` (\`crates/client/src/effects.rs\`) never resets \`quality.ready\`, so after a level change emitters don't wait for the first \`TS_DrawEffects\` the way they do in TS.
