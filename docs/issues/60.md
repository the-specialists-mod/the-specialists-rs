## Description

Follow-up to #44, #52 and #58: keep one type and one wrapper per engine call.

- **Cvars:** `goldsrc::client::Cvar` and `goldsrc::ext::render::Cvar` are separate types. `client::Cvar::register` registers straight away; `render::Cvar::register` first looks for an existing cvar and only registers if there isn't one. `ClEngine::register_variable` and `cvar_pointer` in `ext/hud.rs` are a third set of wrappers. The game crates use both types (e.g. `studio.rs` and `view.rs` use the render one; `hud/mod.rs` and `input.rs` use the client one). Decide which registration rule wins.
- **`pfnGetScreenInfo`, `pfnDrawConsoleString`, `pfnFillRGBA`:** `client.rs` and `ext/hud.rs` both wrap them: `screen_size` / `screen`, `draw_string` / `draw_console_string` (the second also returns the x after the text), and `fill_rgba` / `fill`.
- **`pfnGetLevelName`:** `ext/voice.rs` `in_level` and `render::level_name`.
- **`GetSpritePointer`:** `ext/voice.rs` and `render::sprite_model`.
- **TriAPI `RenderMode` / `SpriteTexture`:** `ext/tri.rs` and `ext/studio.rs` (`tri_render_mode`, `chrome_sprite_texture`).
