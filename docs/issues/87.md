## Description

Server differences from \`ts_i386.so\` (Ghidra addresses), found while working on #86:

1. **\`CHalfLifeTeamplay::ClientUserInfoChanged\` (0xe4d18) isn't ported.**
   - Changing your \`model\` re-rolls a team model when there is a team limit.
   - Without a limit, it changes your team (message, \`ChangePlayerTeam\`, \`RecountTeams(true)\`). This is how players pick a team when there is no team list.
   - Under \`mp_defaultteam\` it puts the \`model\` and \`team\` keys back.

   The port's \`userinfo_changed\` (\`crates/server/src/rules/lifecycle.rs\`) only handles name changes and an HLDM model check. That model check also differs from \`CHalfLifeMultiplay::ClientUserInfoChanged\` (0x8b244), which has a \`PlayerIsCheating\` → \`cl_lw\` branch and compares the \`model\` key with the team name.
2. **The One's team switch.** \`SelectRandomTheOne\` and \`TheOneIsDead\` (\`CTSGameRules.c:2189\`, \`:2270–2275\`) call \`SetDefaultPlayerTeam\` and then \`ChangePlayerTeam(TeamID, 0, 0)\`, which sets the keys and sends \`ScoreInfo\` and \`TeamNames\`. The port's \`teams::the_one_teams\` (\`crates/server/src/rules/teams.rs\`) only renames the team and sends \`TeamInfo\`.
3. **\`game_player_team\` isn't ported.** TS exports it (0xcd740), and \`CGamePlayerTeam.c:47\` calls \`ChangePlayerTeam\`. There's no such entity in \`crates/\`.
