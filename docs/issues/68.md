# #68: Thrown knives set pev->owner, which TS doesn't; the thrower's glow is keyed off it

- State: closed (completed)
- Labels: bug, integration
- Opened by Azerothian on 2026-10-10, closed on 2026-10-10
- Originally CrunchyMonkies/rust-hlmod-the-specialists#68

## Description

**What TS does:** `CTSKnife::CreateKnife` (0x7d9e4; objdump 0x6d9e4) stores the thrower only in the private field at +0x8c and never writes `pev->owner`. Neither do Spawn (0x7db54), `KnifeFire` (0x84044) or `KatanaThrow` (0x83b68).

**What the port does:** `Knife::spawn` (`crates/server/src/weapons/projectiles.rs`) sets `pev.owner = owner`. As a result:
- The engine never collides a knife with its thrower. In TS the knife bounces off them without hurting them (`BounceTouch` returns early for the owner).
- The thrower is sent as `entity_state.owner`.
- `add_to_full_pack` in `crates/server/src/net.rs` gives the thrower's glow shell based on `v.owner == host`. TS's `AddToFullPack` (0xaf180, `server/decomp/global_000ab05c.c` around line 1941) reads the knife's +0x8c instead, and for `WorldGun` its +0xd0. `weapons::glow_for_host` (`crates/server/src/weapons/mod.rs:377`) reads those private fields but is never called.

**Fix:** drop the knife's `pev.owner` and have `net.rs` use `glow_for_host`. First check that `WorldGun`'s `dropper` field matches TS's +0xd0. #1's thrower credit is stored separately (`projectiles::Thrower`), so it doesn't depend on `pev.owner`.

Recorded as a deviation in `weapons.md` (#66) for now.
