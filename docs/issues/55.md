# #55: Explosion damage through walls skips the player TraceAttack step (spawn protection, stunt ×0.7, PTakeDam)

## Description

TS `TSExplosion` (0x7d01c) always calls `victim->TraceAttack` (vtable +0x54, at 0x7d635) and then `ApplyMultiDamage`. That includes the occluded case, where it passes the back trace from the target, which ignores the target. `CBasePlayer::TraceAttack` (0x901cc) applies spawn protection (`pl+0x71c`), the stunt/dodge ×0.7, the team check and the `PTakeDam`/hit sounds.

The port has a single damage entry point. `take_damage` in `crates/server/src/player/damage.rs` (around line 72) treats damage as traced only when `hitgroup != GENERIC` or `DMG_BULLET` is set. `ts_explosion` in `entities::stock::explode` passes the trace's `iHitgroup`, but the back trace (`ignore = victim`) never hits the victim, so its hitgroup is 0. The same happens for a line-of-sight trace that ends without hitting a hitbox.

So a grenade or exploding breakable going through a wall skips spawn protection and the stunt reduction.

Fix idea: add an explicit `traced: bool` to `DamageInfo` (`crates/server/src/damage.rs`) and set it from every TraceAttack-style caller.
