## Description

Client differences from TS's \`client.dll\`, found while working on #75:

1. **Gun re-init on respawn.** Right after the player's Spawn, \`HUD_WeaponsPostThink\` calls 0x100083f0 on the gun (at 0x100038c3).
   - Through 0x10008470 that clears much of the gun object (\`0x104…\`, \`0xc4…\`, \`0x83c…\`), sets \`m_iId = 0x10\`, and zeroes \`0xb8\`, \`0x89c\` and \`0x8a0\`.
   - The port's \`post_think\` (\`crates/client/src/prediction/gun.rs\`, \`Pred::gun\`) keeps the rest of the non-networked \`Gun\` state across a respawn.
   - Map those offsets to port fields and reset them the same way.
2. **Holster on death.** When health goes from >0 to ≤0, TS calls the player's Killed (0x1000389b → 0x100036b0). That calls the active item's Holster (vtable +0x128 = 0x1000aaf0 → 0x1000ab00). The port does nothing on that transition. Port what Holster does to the predicted state.
3. **Emitter details** (\`crates/client/src/effects/emitters.rs\`, \`emit\`):
   - TS rejects only a particle count of 0 (0x1003ac6d); the port rejects ≤0.
   - TS looks up the template sprite after the camera test, and prints a message if it's missing (0x1003ae5f–0x1003ae78). The port looks it up before drawing the random particle count, so a missing sprite changes the random sequence.
