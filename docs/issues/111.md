## Description

Found while working on #110 (checked in `ts_i386.so` and the port; Ghidra addresses):

1. **`IsPlayer()` vs `FL_CLIENT`.** TS's `IsPlayer()` virtual is true for any player object, including one whose client has left. The port's `is_player` checks `FL_CLIENT`, which is cleared on disconnect. Known sites:
   - `rules/scoring.rs` vs `PlayerKilled` (0x895e4): an attacker who has left (for example after throwing a grenade) is scored as a world kill in the port.
   - `rules/powerup.rs` vs `SlowMotionFlow` (0x96bb0): players who have left are skipped.
   - `rules/lifecycle.rs` vs `Observer_FindNextPlayer` (0x99b0c): differs only during intermission.
   - `player/damage.rs` vs `TraceAttack` (0x901cc).

   Go through every `is_player` site in the server, and use `has_player` (#110) wherever TS calls `IsPlayer()` or compares the classname.
2. **`ammocount`.** `weapons/assets.rs` clamps and truncates it. TS's `Set_ammo_count` (0x7f2cc), applied by `CTSGameRules::Think`, rounds it and maps any value other than 1–3 to the default column. So `ammocount 5` gives zero max carry in the port but the default carry in TS.
