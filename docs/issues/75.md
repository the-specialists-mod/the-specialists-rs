## Description

Client differences from TS's \`client.dll\`, found while working on #74:

1. **Initial slow-motion target.** The target \`0x1009ff04\` lies past the initialised 0x8000 bytes of \`.data\` (0x10091000–0x10099000), so in TS it starts at 0.0. The port starts it at 1.0 (\`crates/client/src/state.rs\`, \`time_scale_target: 1.0\`). Until the first \`TSSlowMo\` arrives, TS eases the scale toward 0. The port's server sends \`TSSlowMo\` on the first client update, which mostly hides this. Check whether it can be seen (e.g. on demo playback, or on servers that don't send it) and match TS.
2. **Respawn spread reset.** When health goes from ≤0 to >0, \`HUD_WeaponsPostThink\` calls 0x100036d0 (at 0x100038be). That runs the draw animation (vtable +0x120) and then calls 0x1000b9d0 (at 0x100036e7), which resets the spread. The port's \`post_think\` (\`crates/client/src/prediction/gun.rs\`, the \`was_dead && !dead\` path) only replays the draw animation. Use \`prediction::reset_spread()\` from #74.
3. **Emitter behind the camera.** TS skips it for that frame without rescheduling (\`goto LAB_1003b236\` in 0x1003ab40). The port pushes \`next_emit\` back 0.25 s (\`crates/client/src/effects/emitters.rs\`, \`em.next_emit = clock + 0.25\`).
4. **\`FX_AdaptQuality\` timing.** TS runs it from \`TS_DrawEffects\` (0x10056dd0) when \`cl_fx == 1\`. The port runs it from \`effects::frame\` in \`HUD_Frame\` (\`crates/client/src/effects.rs\`). Check the call order and the frame time it gets, then match TS.
