# #58: goldsrc client: duplicate engine wrappers in ext/render.rs and ext/hud.rs, and an unchecked pEfxAPI

## Description

Several client engine calls have both a free-function wrapper in `ext/render.rs` and a `ClEngine` method in `ext/hud.rs`, and the two behave differently:
- `entity`/`local_player`: render returns `&'static mut cl_entity_s`, hud returns `&'static cl_entity_t`. That gives two aliasing views of the same engine memory.
- `max_clients`, `client_time` and `spr_load` are plain duplicates.
- `EV_PlaySound`: `render::play_sound` panics on a null slot, while `ClEngine::ev_play_sound` does nothing.
- Player-trace setup: `render::with_solid_players` calls `EV_SetUpPlayerPrediction` before `EV_PushPMStates`, while `ClEngine::player_trace` pushes first. The SDK sets up prediction first.

Also, `render::efx_api()` does `&*engine().f.pEfxAPI`, which is undefined behaviour if the engine leaves the pointer null. `event_api()` (#44) and `tri_api()` (#52) now go through null-checked `ClEngine` accessors.

Fix: add `ClEngine::efx_api() -> Option<&'static efx_api_s>` behind `efx!`, and keep one wrapper per call, the way #44 and #52 did.
