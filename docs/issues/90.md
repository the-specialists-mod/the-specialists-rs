# #90: Server weapons/damage: pellets summed per victim, game_player_equip without weapon_tsgun, death order and CurWeapon

## Description

Found in the deviation audit (checked in `ts_i386.so` and the port; Ghidra addresses):

1. **Pellet damage.** TS adds every pellet into one total and applies it once per victim (TraceAttack accumulates, then a single TakeDamage). The port applies each pellet on its own. Fixing this means splitting the player's TraceAttack from TakeDamage (`crates/server/src/player/damage.rs` and every `take_damage`).
2. **`game_player_equip`.** On maps with one, TS's `PlayerSpawn` (0x890ac) gives no `weapon_tsgun`, so the player has no gun. The port always gives one.
3. **Death order.**
   - TS's `Killed` (0x8ed5c) drops the flag before the weapon loop, and calls `Animate(7)` after it. The port calls `animate(7)` before the drops and `drop_flag` after (`rules/lifecycle.rs`).
   - TS's `PlayerDeathThink` (0x8eaec) calls `RemoveAllItems(1)` when the player has weapons, which sends `CurWeapon 0,0,0`. The port's `death_think` doesn't, so `CurWeapon` goes out early from `weapons::on_killed`.
