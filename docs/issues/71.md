## Description

Two client gaps found while porting #69, both checked against the original \`client.dll\`:

1. **\`CL_IsThirdPerson\` (0x1004fec0)** returns only the \`thirdperson\` toggle's flag (\`test ecx; setne al\`). The port's \`view::is_third_person\` (\`crates/client/src/view.rs:658\`) returns \`w.third || w.forced_dead\`, so the death cam also counts.
   - That value feeds events, effects, studio, voice and HUD callers: the crosshair, the weapon HUD, and the death-cam / \`cl_thirdpersonswitch\` checks. Any of these can behave differently from TS while the player is dead.
   - Work out which of those callers TS gates on the toggle's flag and which on the death cam. Then split the function, or document the deviation in \`docs/implementation/client-rendering.md\`.
2. **Demo record types 0 and 1.** TS writes them at 0x10003bf9 and 0x10020a11, and reads them back at 0x10020a25 and 0x1003df6c.
   - The port's \`crates/client/src/demo.rs\` recognises them, but never writes them or does anything when it reads them.
   - The type 0 code sits next to TS's sensitivity getter (0x10020a90), so it may record zoom or sensitivity.
   - Find out what both types hold and port them.
