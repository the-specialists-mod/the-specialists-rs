# #69: Third-person camera controls: TS's +cam* commands and the thirdperson toggle aren't ported

## Description

Two parts, both checked against the original `client.dll`:

1. **Camera control commands.** TS's `CAM_Init` (0x10025370) registers `+/-campitchup`, `+/-campitchdown`, `+/-camyawleft`, `+/-camyawright`, `+/-camin`, `+/-camout`, `+/-cammousemove`, `+/-camdistance` and `snapto` (which toggles `cam_snapto`).
   - `CAM_Think` (0x10024c80) uses them to adjust `cam_idealpitch/yaw/dist` by 2.5° or 1 unit per frame, bounded by `c_min/max*`, and drags with the Win32 cursor in the mouse modes.
   - The port has none of them, so the `c_*` cvars (registered in #65) are never read, and binds to these commands print "unknown command".
2. **`thirdperson` is a toggle in TS.** The handler (0x1004fe00) flips `cam_thirdperson`, seeds `cam_ofs` = (view pitch, view yaw, 30), sets `cam_command 0`, and records a demo marker while recording.
   - Outside demo playback it refuses to switch while observing, unless already in third person. During playback it returns early in one `cam_thirdperson` state (the condition isn't confirmed).
   - `view::cmd_thirdperson` just sets third person on, with no observer check or demo marker. So a bound `thirdperson` key (or `cam_command 1`) can't toggle back as in TS.
   - Check whether xtask scripts rely on the current set-only behaviour before changing it.

Port both in `view.rs`, or note them under Deviations in `docs/implementation/client-rendering.md`.
