## Description

Found while working on #101 and #102 (checked in `ts_i386.so` and the port; Ghidra addresses):

1. **`UpdateOnRemove`.** `UTIL_Remove` (0xeea90) and `SUB_Remove` (0xe2d40) call `UpdateOnRemove` (0xe2ccc), which marks a removed entity's `globalname` as dead in the global state. The port's `entities::remove` and `base::sub_remove` don't.
2. **Monster `TakeDamage`.** `env_explosion` and `cycler_wreckage` use `CBaseMonster::TakeDamage` in TS (`vtables.tsv`); the port gives them the base function (`entities/stock/effects.rs`). Check every class's `TakeDamage` vtable slot against the port.
3. **Gun entity from `GiveNamedItem`.** A gun given at spawn or by `game_player_equip` has no entity in the port, so an armed player uses one edict fewer than in TS, and edict numbers differ. Give it an entity, as TS's `CTSGun` has.
4. **Per-class precaches.** #102 ported the map-wide precache sequence and checked only doors, plats, trains, `gibshooter` and two item classes. Audit every class's `Precache` (order and set) against TS, since the precache order decides model and sound indices.
5. **Blood splat.** `player/impulse.rs` `CBloodSplat::Spray` still draws its decal with `sv_language 1` (check TS's language test), and `impulse::precache` is now unused.
6. **Single-player gun holster.** In single player TS holsters a held gun to deploy a picked-up `cycler_weapon`, and `use cycler_weapon` can switch to it later. The port's gun can't be holstered.
7. **`game_player_team` from the weapon frame.** It still defers when fired from the player's own weapon frame (e.g. shooting a button), because the frame holds the gun. Find a way to reach the player mid-frame, as TS does.
8. **Save data.** The port writes no entity save data, so the transition list exists but entities never cross a level change (`trigger_changelevel` in single player/co-op). Port `Save`/`Restore` and the engine save callbacks as TS has them.
