# #1: Grenade in-flight impact damage is credited to the grenade, not the thrower

- State: closed (completed)
- Labels: bug, integration
- Opened by Azerothian on 2026-10-10, closed on 2026-10-10
- Originally CrunchyMonkies/rust-hlmod-the-specialists#1

## Description

## What happens

When a thrown M61 hits something while still flying fast, `impact_damage`
(`crates/server/src/weapons/projectiles.rs`) builds the damage as
`DamageInfo::new(me, me, dmg, bits)`. The grenade entity is both the inflictor **and the attacker**.
So the damage is credited to the grenade, not the player who threw it.

The `cargo xtask dojo` run showed it. A breakable hit by the flying grenade logged an empty
attacker name, while the same grenade's explosion credited the thrower:

```
[ts] func_breakable #33 broken by  (grenade, damage bits 0x1080)        <- flying impact
[ts] func_breakable #20 broken by [LOCO]BKD (grenade, damage bits 0x1040) <- explosion
```

Knives and thrown world guns go through the same helper, so they're probably affected the same way.

## Why it matters

Anything keyed on the attacker sees the grenade instead of the player:
- breakable `fuser1` (the slow-motion scale is copied from the attacker),
- kill credit or logging if a flying projectile ever finishes something off,
- team or friendly-fire checks.

## What to check

The decomp notes (`ts30-decomp/docs/server/weapons.md`, "Flying impact") say the impact deals
`speed × 0.1` (bits `0x1080`) when that's at least the target's health. They don't say which
attacker TS passes. Confirm in the decomp (`CTSGrenade::BounceTouch` / the 0.1 s think around
`CM61Grenade` 0x7c850) whether TS uses `pev->owner`. If it does, pass the owner as the attacker
(falling back to the projectile when there's no owner).

## How to verify

`cargo xtask dojo fwgs`: with the fix, the in-flight `func_breakable ... broken by` line should name
the thrower.
