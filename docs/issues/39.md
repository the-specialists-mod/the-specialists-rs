# #39: Entity keyvalues reach the class before the entvars fields (the SDK parses entvars first)

- State: closed (completed)
- Labels: bug, integration

- Originally CrunchyMonkies/rust-hlmod-the-specialists#39

## Description

In the SDK and TS, `DispatchKeyValue` parses `entvars_t` fields first and only passes unhandled keys to the class `KeyValue`.

The port's `key_value` in `crates/server-dll/src/lib.rs` does the reverse: it calls the class first and falls back to `entities::entvars_key_value`. So a class whose own keys share a name with an entvars field gets that key, and the entvars field is never set. `multi_manager` already works around this. It's documented as integration note 1 in `docs/implementation/stock-entities.md` §6, but nothing tracks fixing it.
