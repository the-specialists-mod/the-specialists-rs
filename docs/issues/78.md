## Description

Weapon prediction differences from TS's \`client.dll\` (\`HUD_WeaponsPostThink\`, 0x10003…), found while working on #76. The port's code is in \`crates/client/src/prediction/gun.rs\` and \`crates/client/src/view.rs\`.

1. **Weapon switches aren't predicted.** TS runs \`SelectWeapon\` + \`Deploy\` when the id changes (0x10003d92–0x10003dc1). Deploy covers the draw event, the fire-mode memory, and the status-state / alt-grip reset. On respawn it runs Deploy (vtable +0x120). The port only plays the draw animation.
2. **\`gun_from\` ignores the \`m_iId\` gate.** TS copies \`weapon_data\` and rebuilds the slot only when \`from.m_iId == 16\` (the \`local_68\` gate at 0x10003965). The port always does both.
3. **Weapon records are rebuilt every command.** \`gun_from\` resets all 38 records on each command. TS keeps them until the gun's Spawn (0x100083f0, on respawn and after VidInit, as ported in #76).
4. **The VKickback clock.** TS times the kick (\`+0x8c0\`) with the prediction time (\`*0x10099114\`). The port's \`view::kick_angles\` uses \`engine().client_time()\`.
