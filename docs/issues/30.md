# #30: Game crates call the engine macros directly, breaking the unsafe boundary

- State: closed (completed)
- Labels: bug, integration
- Opened by Azerothian on 2026-10-10, closed on 2026-10-10
- Originally CrunchyMonkies/rust-hlmod-the-specialists#30

## Description

AGENTS.md rule 2 says game crates must not use `eng!`/`cl_eng!`/`ev!`/`efx!`/`tri!`, because they expand to `unsafe` at the call site. It compiles anyway: `#![deny(unsafe_code)]` doesn't fire on unsafe blocks that come from another crate's macro.

Current uses:
- **ts-server:** `World::key_value` in `crates/server/src/entities/stock/mod.rs` calls `goldsrc::eng!(pfnCVarSetString(...))` for `sv_skyname`. The safe `Engine::set_cvar_string` (`goldsrc/src/ext/rules.rs`) already exists.
- **ts-client:** `effects/laser.rs` (26 uses), `effects/psys.rs` (9), `view.rs` (4: `SetViewAngles`, `V_CalcShake`, `V_ApplyShake`), `effects.rs` (2), `menus/mod.rs` (2), `events.rs` (1), `prediction.rs` (1).

Fix: add safe wrappers to `goldsrc` (e.g. `ext/render.rs`) and switch the call sites. Also consider a check that catches this automatically, e.g. a grep in `cargo xtask build` or a clippy `disallowed_macros` config.
