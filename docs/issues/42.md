# #42: View-height smoothing starts from the first frame's view height; TS starts at 0

## Description

TS `V_CalcNormalRefdef` (`0x10067890`) eases the view height in a static at `0x10191d90`: `vh += (viewheight.z − vh)·min(15·ft, 1)` (`0x100679ee..0x10067a43`). The static is zero-initialised (it lies past the `.data` raw size, so in BSS) and never reset.

`calc_normal` in `crates/client/src/view.rs` sets `w.vh = p.viewheight[2]` on its first call (the `initialised` block). So on the first spawn after the library loads, the eye doesn't ease up from the origin the way TS's does.

It's minor, and it now overlaps with the stair smoothing's own ease from z 0 (#31). Port it, or record it as a deviation in `docs/implementation/client-rendering.md`.
