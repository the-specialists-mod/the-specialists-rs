## Description

Server differences from \`ts_i386.so\` (Ghidra addresses), found while finishing #7:

1. **\`jointeam\`.** TS's \`ChangePlayerTeam\` (0xe488c, code at 0xe4c38..0xe4ca1) always starts observer mode and calls \`SetPlayerRespawnTime(5)\` unless it's a kill or The One mode. The port's \`jointeam\` (\`crates/server/src/rules/commands.rs\`):
   - skips a change to the same team;
   - only starts observer mode when not already observing;
   - sets \`respawn_at\` directly, so the respawn award 11 is never sent.

   TS's teamplay \`InitHUD\` (0xe45d8) also goes through \`ChangePlayerTeam\`, but the port's \`teams::init_hud\` doesn't start observer mode.
2. **\`fullupdate\`.** TS's \`ForceClientDllUpdate\` (0x92594) sends a \`Spectator\` message. The port (\`commands.rs\`, \`"fullupdate"\`) sends none, and sets \`init_hud\`, which TS doesn't.
3. **\`CallCheckDeads\` (0x79bc0).** TS only schedules the check when no round restart is pending. The port schedules it every time, for example in \`scoring.rs\` and \`lifecycle.rs\`. The effect is small, because \`check_deads\` returns during a restart anyway.
