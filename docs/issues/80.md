# #80: Client view: V_CalcBob and V_CalcGunAngle differ from TS; normal view ignores spectator camera overrides

## Description

Differences between TS's view code (\`client.dll\`) and \`crates/client/src/view.rs\`, found while finishing #6 and #7:

1. **\`V_CalcBob\` (0x10066e70, decomp lines 149–255) vs \`view::calc_bob\`:**
   - TS returns 0 in third person and while spectating. It also returns 0 when the \`PM_SpectatorMove\` smoothing flags are set without bit 8 (decomp line 165).
   - TS only advances the bob on the ground, when the time has changed and the view height isn't 0.
   - TS resets the phase to 0 above 360; the port wraps it at 720.
   - The amplitude logic is different.
   - TS applies the gun offset as a world-space mix of the previous frame's forward/right/up vectors. The port uses three per-axis multipliers.
2. **\`V_CalcGunAngle\` (0x100674a0):** TS sets the gun angles to \`(bob − viewangles.pitch, viewangles.yaw, viewangles.roll)\`, so the gun takes the bob pitch and the stunt roll, and \`crosshairangle\` isn't used. The port (\`calc_normal\`: \`vm.angles = [-base_angles[0] + p.crosshairangle[0] * 0.25, base_angles[1] + p.crosshairangle[1], base_angles[2]]\`) uses the SDK's \`crosshairangle\` terms, with no bob pitch.
3. **Spectator overrides in the normal view.** \`V_CalcNormalRefdef\` also reads the camera overrides that client \`PM_SpectatorMove\` sets (\`0x101914f0\`/\`0x1019149c\`, around \`unnamed_10066c80.c:645-667\`). The port's normal view doesn't. This only matters in frames where the movement code and the HUD disagree about the observer mode, or after an HLTV director reset.
