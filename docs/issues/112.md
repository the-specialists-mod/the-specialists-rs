## Description

Found while working on #111 (checked in `ts_i386.so` and the port; Ghidra addresses):

1. **`realbullet`.** TS's Think stores the truncated value (0x775cc–0x775f0). Its change check compares that stored int with the float cvar, so a fractional value re-sends `SrvSett 0` on every Think. The port rounds and compares as integers (`rules/frame.rs`). `weapons/assets.rs` also rounds the live cvar, instead of using the copy Think updates.
2. **`usecash`.** Think stores the truncated value and sends whether it's non-zero (0x77666–0x776c9), so 0.5 sends 0, and it re-sends on every Think. The port sends `cvars::on` (so 0.5 sends 1), and only when the value changes.

Check every other cvar copy in `CTSGameRules::Think` for the same pattern (truncate with the FPU in truncating mode, compare the int with the float).
