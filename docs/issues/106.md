# #106: Server: free slots and items reset on StartObserver/disconnect; weapon net caches at spawn

## Description

Found while working on #105 (checked in `ts_i386.so` and the port; Ghidra addresses):

1. **Free slots.** `strip_all` (`crates/server/src/weapons/mod.rs`) resets the free-slot count to 81, clears the bought items and recomputes the speed. TS's `RemoveAllItems` (0xd8cec) and `StartObserver` (0x99634) never touch those fields; only `TSInit` (0x92a4c: slots 0x51, items 0) and the item and weapon code change them. Because `player/hud.rs` sends `TSSpace` whether or not the player is alive, a player who starts observing while holding weapons gets `TSSpace 81` and a maxspeed change that TS doesn't send. The spawn has to set the slots the way `TSInit` does.
2. **Weapon net caches at spawn.** `on_spawn` calls `reset_net`, which sets the last-sent weapon id to `None`. On a new gun, TS's `CTSGun::Reset` sets it to 0 (`CTSGun.c:153`), and `UpdateClientData` (0x858c8) sends `WeaponInfo` only when the current weapon differs. So TS sends no kung-fu `WeaponInfo` on a fresh gun, but the port sends one at every spawn. TS also keeps the caches for a gun that is still held through a spawn.
