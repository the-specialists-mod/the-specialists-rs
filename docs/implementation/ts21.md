# The TS 2.1 gameplay plugin

`ts_gameplay 21` makes the server play by TS 2.1's rules, the April 2004 `mp.dll` and
`client.dll`. The decomp's reports are in `docs/ts21/` and posted on issue #100. The plugin is
the crate `crates/ts21` (package `ts21-gameplay`). It plugs into the hooks described in
[gameplay-plugins.md](gameplay-plugins.md), and the 3.0 crates never name it.

## Status

**Skeleton (issue #100 checklist item 1).** The plugin is registered on both sides and
selectable end to end: the cvar, physinfo `gp`, `SrvSett` 4 and the reset on a switch all work.
Item 3 (shared weapons) is done: see below. Items 2-14 of the issue's checklist
add the 2.1 rules here, each with any hook it needs (added to the 3.0 crates with the 3.0
behaviour as the default).

## Layout

| Package (directory) | Implements | Linked by |
|---|---|---|
| `ts21-gameplay` (`crates/ts21`, `src/shared/`) | `shared::gameplay::PmRules` and `GunRules` on `Ts21`: movement and the gun, which the server and the client's prediction both run (issue §2). The id `"21"` | both libraries |
| `ts21-server` (`crates/ts21/server`) | `ts_server::gameplay::ServerRules` on `Ts21Server` (issue §3), and the server's `PLUGIN` | `server-dll` |
| `ts21-client` (`crates/ts21/client`) | `ts_client::gameplay::ClientRules` on `Ts21Client`: HUD and input (issue §4), and the client's `PLUGIN` | `client-dll` |

The side hooks are packages of their own, not cargo features, so a build of both libraries never
links the server crate into the client library or the other way round
([gameplay-plugins.md](gameplay-plugins.md) §1). `server-dll` registers `ts21_server::PLUGIN`
under the id `"21"` at `GameDLLInit`, and `client-dll` registers `ts21_client::PLUGIN` at
`Initialize`. Both do it behind their default-on `ts21` feature, so `--no-default-features`
builds 3.0 alone.

## Rules

* Match TS 2.1 exactly, including its oddities, as the port matches 3.0 (AGENTS.md). Cite the
  2.1 function and address (`mp.dll`/`client.dll` VAs, `0x1000xxxx`) in doc comments.
* The wire format stays 3.0's (issue #100 §1.2). The plugin carries 2.1 values in 3.0's messages.
* Never copy behaviour that crashes, hangs or stops the engine. Guard it and list it below.

## Shared weapons (issue #100 §2.3, checklist item 3)

`crates/ts21/src/shared/gun.rs` (`GunRules` on `Ts21`) and `tables.rs`, run by the server and the
client's prediction alike. Addresses: 2.1 `mp.dll`, and 2.1 `client.dll` where marked.

* **Tables** (`data/weapons21.toml`, `ammo21.toml`, `assets21.toml`, `combat21.toml`): decoded
  from the 33 `Write_*` writers `FUN_10049890` calls, `compile_ammo_info` (0x10049420) and
  `Set_ammo_count` (0x100492a0); the generator read the decomp's stores and `mp.dll`'s strings.
  No ids 2, 36, 37; 17 is the STEYR-TMP (with its own models, sounds and view-model sequences);
  the UMP has no burst; ammo .454 is type 12. `WeaponInfo::damage` is the ammo's integer base
  damage times the weapon's multiplier (`tables::ammo_damage` and `tables::damage_multiplier` give
  the two factors; 2.1's `ShootBulletsPlayer` multiplies `base x range x mult`). `stock` is 20 on
  the M4 and Sawed-off only. Blades and grenades have no ammo, so their table damage is 0 (2.1's
  blade code hard-codes its damage). The view-model sequences are TS 3.0's except the TMP's:
  they index the 3.0 models the port plays with (3.0 added stock, throw and block sequences and
  replaced `v_ump.mdl`; `v_tmp.mdl` is the same file in both).
* **Timers**: delays are fixed when set, `delay x T` with `T = fuser1 ? 1/max(fuser1, 0.1) : 1`
  (the client's `FUN_100261b0` has no 0.1 floor), or `x 6.6666665` for the Slow Pause owner (the
  client divides by 0.15); the timers run down by the raw frame time (server `PostThink`
  0x10054180, client `FUN_10017f70` with `msec / 1000.0` unrounded). Double fire rate halves the
  rate of auto, shotgun and akimbo delays (not semi or burst).
* **StandardFire** (0x1004b400): the round first; silencer spread x1.2 and damage x0.8; a Barrett
  or M60 above 80 u/s sets the penalty to 0.1; semi waits the rate. **ShotgunFire** (0x1004b050):
  semi 0.1 s, kick x1.3 in semi, no silencer. **AkimboFire** (0x1004b8c0): every bullet 4 units
  off-centre (linked `toggle ? -4 : +4` then the other side; one gun `toggle ? +4 : -4`), semi 0.1.
  **Fire** (0x1004ac20): no Infinite Clip bypass of the empty click. **EmptySound** (0x1004ab60):
  `T x 0.1`, no Contender exception.
* **ScaleSpread** (0x10049a50, client 0x1001e660): `k = DFR ? 1 : 2`, no silencer factor,
  `x = dt / T`, any `dt >= 0`.
* **VKickback** (0x10049b80, client 0x1001e8e0): random sided yaw `(s·u ± 0.5 ∓ r2)·kick·0.65`;
  the client's pitch is `p·s`, the server's (bots) the kick itself; no view shake. HL's shared
  random float truncates its range to an integer, so `r2 = SR(seed+2, 0, 0.75)` is always 0 and
  `p` spans `trunc(kick/2)` from `kick/2` (the decomp report's "U(kick/2, kick)" is the intent).
* **Pellets**: HL's triangle (`ShootBulletsPlayer` 0x1003fd40, client `FUN_1007c190`); a bot's
  use the engine's `RandomFloat` with redraws outside the unit circle.
* **Spread decay** on elapsed game time (`PreThink` 0x100537e0 while alive; client
  `FUN_10017f70` on a first prediction with the HUD's slow-motion scale), no DFR factor.
* **Prediction** (client `FUN_10025f40`): no +alt2, no kung-fu reload key, no clip refill when a
  magazine reload finishes. **Gate** (`FUN_1002d840`): +alt2 lets the frame run in any magazine
  reload.

Left to other items: bullet damage order, penetration step and the client event's mirror of
them (the event still uses 3.0's x0.775 silencer and 2·left step), melee, knives, the stock hit
and grenades (item 4/5), the server's PreThink melee-bar and window timers (item 5), the HUD
weapon sprite for id 17 and the client event's own view-model sequence table for id 17 (item 13).

## Deviations

* The client's kick target and a bot's `punchangle` add the kick's yaw as a rounded `float`;
  2.1 adds the unrounded product (at most one ulp apart).
* The server and the client event combine a pellet's direction as TS 3.0's code does (single
  precision); 2.1 sums it on the FPU (at most one ulp apart).
* The client's view-angle kick target uses TS 3.0's smoothing; 2.1's (`FUN_10097de0`) wasn't
  compared.
